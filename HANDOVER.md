## 1. What this project is

A Decky plugin + standalone web app that maps any game controller
(guitars, drum kits, fightsticks, pads) into **real Steam Input VDF profiles**,
and publishes them where SteamOS actually reads them.

- Repo: `~/Work/projects/deckforge-input-studio` (also `NaustudentX18/deckforge-input-studio`)
- Installed on the Deck at `/home/deck/homebrew/plugins/DeckForge Input Studio`
- Backend: FastAPI + evdev on `:8765`. Frontend: React, two bundles —
  `dist/index.js` (Decky QAM) and `static/dist/web-entry.js` (web/PWA).

## 2. The five things that were broken and are now fixed

Each was proven by probing hardware, not by reading code. If you touch any of
these areas, verify you have not reintroduced them.

| # | Problem | Why it matters |
|---|---|---|
| 1 | Decky's interpreter is a **frozen CPython 3.14** that cannot see pip packages | deps must be vendored in `py_modules/lib` (cp314, x86_64) |
| 2 | Decky adds only `<plugin>/py_modules` to `sys.path` | import `deckforge.*`, never `py_modules.deckforge.*` (double-imports) |
| 3 | `"flags": ["root"]` sets `HOME=/root` | every `Path.home()` Steam path silently misses |
| 4 | The frozen stdlib **lacks `logging.config`** | uvicorn dies at import; `deckforge/compat.py` shims it |
| 5 | Templates were written to directories **that do not exist** | Steam reads `controller_base/templates/` only |

Also load-bearing: the VDF compiler **patches Valve's own shipped skeleton**
(`py_modules/deckforge/data/controller_neptune_base.vdf`), because Steam's schema
is group-based and analog output is a group setting, not a binding. Do not
hand-roll a `controller_mappings` body.

## 3. Hardware facts you must not re-derive

The CRKD Gibson Les Paul Pro (Blueberry Burst) is the flagship device:

- **CRKD's own ids are `0351`/`3651`** (PlasticBand: PS4 `1500`/`5500`, PS5
  `1600`/`5600`, Xbox One `4161`; SDL additionally lists `1000`/`2000`/`6000`).
- **`20BC:5500` is NOT a CRKD id.** It is ShenZhen ShanWan (a USB bridge
  vendor); usb.ids calls `20bc:5500` "Frostbite controller" and SDL classifies it
  as a *PS3* controller. A unit labelled "CRKD Gamepad" did report it on
  2026-11-13, so it is accepted for detection — but the bridge appears to
  present under ShanWan's id, and **which Mode Dial position was active during
  that capture was never recorded.** Do not read a `20bc` sighting as evidence
  of a dial position, and do not repeat the earlier claim that it is CRKD's
  PC-mode id.
- **The control layout IS measured** (that part stands): whammy `ABS_Z`, tilt a
  digital `ABS_HAT0X` edge, orange fret `BTN_TL`, strum `ABS_HAT0Y`. Those came
  from a direct evdev capture, not from documentation.
- **The Mode Dial changes what the host sees.** 1 guitar default, 2/3/4 Festival,
  5–8 programmable, **9 = KEYJAM on PC (guitar becomes a keyboard)** / RB4 on Xbox.
  This is why a profile carries a required dial position.
- Whammy/tilt are 8-bit axes (byte 41/42), not digital hat tilt.
- SDL is useless here: it calls this guitar a **PS3 controller**, and its mapping
  DB has **zero** guitar entries.

Sources: CRKD product page, CK25GM user guide, firmware v2.0 notes,
`TheNathannator/PlasticBand` (CC BY-SA 4.0).

## 4. Where the code lives

```

  steam_compiler.py    # DeckForge bindings -> Steam VDF (skeleton patching)
  vdf_manager.py       # paths, template CRUD, configset assignment

  device_catalog.py    # built-in CRKD family + mode dial table

  compat.py            # logging.config shim for Decky
  data/                # skeleton VDFs + controller_ids.json (613 ids)
src/
  components/LaunchPage.tsx  # landing page (tabs: Profiles/Hardware/Games/Setup/Refs)
  components/FullStudio.tsx  # the studio itself
  components/icons.tsx       # SVG icon set (never use emoji as icons)
  styles/tokens.css          # THE design system — palette, spacing, type
  styles/base.css            # primitives
  styles/landing.css         # landing only
  styles/index.ts            # AUTO-GENERATED by tools/gen-styles.mjs
```

**Edit the `.css` files, then run `make styles`.** `src/styles/index.ts` is
generated (Decky's rollup has no CSS pipeline, so CSS ships as strings).

## 7. Deck hygiene (will bite you)

- **Decky's loader flaps** when a stale plugin process holds a port. If plugins
  vanish from the QAM: `sudo kill -9 <stale pid>`, then restart
  `plugin_loader.service`. PowerTools' backend on `:44443` is the usual culprit.
- A `Hydra.bak.*` directory inside `plugins/` gets loaded as a second plugin.
  Always back up outside `plugins/`.
- `main.py` sets `sys.dont_write_bytecode = True`; without it Decky's watcher
  sees `__pycache__` writes as source changes and reload-loops.

## 8. Traps specific to this codebase

- **Never trust a profile that binds a control you did not measure.** The first
  CRKD mapping bound the wrong physical control because it assumed generic Xbox
  layout.
- **Emoji are banned as icons** (UI/UX Pro Max rule). Use `src/components/icons.tsx`.
- The landing page is **mobile-first**: unprefixed CSS is the phone layout,
  desktop layers at `min-width: 900px`. Don't add `isCompact` branches; use CSS.
- `apiFetch` derives host **and port** from the page origin. Don't hardcode 8765.
